# temporal-graph-extraction

Проект для семинара "Обработка естественных языков" СПБГЭТУ ЛЭТИ: извлечение графа событий из русскоязычных текстов.

------

## Описание проекта

Проект извлекает ключевые события, участников и временные метки из текста и строит на их основе связный граф.

В основе решения - предобученная модель RuT5 для суммаризации текста и seq2seq-модель, дообученная выделять причино-следственные связи в тексте и преобразовывать полученную информацию в структуру графа (вершины-события и рёбра-связи между ними).

------

## Что делает система

1. Принимает исходный текст.
2. При необходимости сначала выполняет суммаризацию с помощью RuT5.
3. Передаёт текст в модель извлечения событий.
4. Разбирает результат в структуру вершин и рёбер.
5. Строит интерактивный граф и отображает его в интерфейсе Streamlit.

## Формат результата

Система возвращает структуру с:
- `summary` -- сжатый текст, если включена суммаризация;
- `nodes` -- список вершин с событием, участником и датой;
- `edges` -- список рёбер между событиями с типом связи.

Пример узла:
```json
{
  "id": "V1",
  "date": "2019",
  "person": "Не указан",
  "text": "Редактор провёл допрос"
}
```

Пример ребра:
```json
{
  "source": "V2",
  "target": "V1",
  "type": "causes"
}
```

## Запуск сервиса

Проект упакован в Docker и состоит из трёх сервисов:

- `model-downloader` -- автоматически загружает модели с Hugging Face;
- `backend` -- REST API для извлечения графа событий;
- `frontend` -- пользовательский интерфейс на Streamlit.

### Требования

- Docker
- Docker Compose v2

### Запуск проекта:

1. Склонируйте репозиторий.
2. Для сборки и запуска выполните в корне проекта:

```bash
docker compose up --build
```

> При первом запуске загрузка модели может занять несколько минут. Последующие запуски используют сохранённую модель из Docker volume и не требуют повторной загрузки.

После старта доступны:

- **Backend API:** http://localhost:8000
- **Swagger-документация:** http://localhost:8000/docs
- **Пользовательский интерфейс:** http://localhost:8501

## Структура проекта

- `data/` -- обучающий датасет (`df_text2graph.jsonl`).
- `notebooks/` -- ноутбуки для подготовки данных и обучения модели.
- `src/` -- исходный код ядра системы.
  - `graph/` -- сборка, построение и визуализация графа.
  - `graph_extraction/` -- обёртка над дообученной seq2seq-моделью.
  - `summarization/` -- обёртка над моделью суммаризации RuT5.
  - `config.py` -- константы, пути, источник модели.
  - `pipeline.py` -- полный пайплайн: текст → (суммаризация) → граф.
- `service/` -- веб-сервис (`backend` - REST API, `frontend` - Streamlit UI).
- `tests/` -- автоматические тесты.
- `docker-compose.yml` -- конфигурация для контейнеризации.
- `.github/workflows/` -- конфигурация CI (GitHub Actions).

> Модели суммаризатора и извлечения событий не требуется скачивать вручную. При первом запуске Docker Compose отдельный сервис `model-downloader` автоматически загружает модели с Hugging Face в общий Docker volume. После успешного скачивания запускается backend, который использует модели из volume.

## Тестирование

Проект содержит автоматические модульные тесты на парсер вывода модели, сборку графа, оркестрацию пайплайна (с имитацией моделей без загрузки весов) и REST API.

### Локальный запуск

```bash
pip install -r requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cpu
pytest tests/
```

> Тяжёлые интеграционные тесты на реальных моделях помечены `@pytest.mark.slow`. Изначально закомментированы.

### CI

В GitHub Actions тесты выполняются автоматически при любом push в `main` и при создании pull request. Также в CI проверяется сборка Docker-образов backend'а и frontend'а.

## Этапы разработки проекта

### 1. Подготовка данных

В ноутбуке `notebooks/preprocessing.ipynb`:
- на основе текстов со словами-маркерами причинных и временных связей строится детерминированный алгоритм извлечения графа;
- слова-маркеры для части текстов удаляются (чтобы модель училась находить связи и без явных союзов), связи при этом сохраняются;
- итоговые пары `текст → граф` сохраняются в `data/df_text2graph.jsonl`.

### 2. Обучение модели

В ноутбуке `notebooks/rut5_trainer.ipynb`:
- загружается датасет `df_text2graph.jsonl`;
- данные преобразуются в формат seq2seq;
- обучается модель на базе `cointegrated/rut5-base`;
- обученная модель сохраняется и тестируется на примерах.

### 3. Сервис и тестирование

- Реализован веб-сервис: REST API (backend, FastAPI) с удобным интерфейсом (frontend, Streamlit).
- Написаны модульные тесты на парсер, модели графа, сборщик графа, пайплайн (с имитацией моделей) и API.
